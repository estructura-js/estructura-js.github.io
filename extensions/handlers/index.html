Handlers

Descripción

Motor declarativo de alta abstracción orientado a la gestión, orquestación e interconexión de flujos de lógica (handlers) desacoplados a nivel de interfaz. Permite mapear elementos del DOM directamente con lógica de JavaScript a través de atributos descriptivos de datos (dataset), proporcionando flujos de ejecución secuenciales, encadenamiento mediante middlewares y control dinámico de estados de éxito y error mediante asignaciones reactivas.

Librería: estructura.handlers.js

Dependencias obligatorias: estructura.dom.js (DOM, documentación), estructura.events.js (Events, documentación). Extensiones requeridas junto con sus objetos globales accesibles (_dom, _events) para consultar elementos e inyectar escuchadores de eventos del DOM. Deben estar disponibles en el entorno antes de inicializar _handlers; de lo contrario, el proceso se interrumpirá emitiendo una excepción en consola.

Documentación

1. Inicialización y Dependencias Directas

El motor expone globalmente la interfaz _handlers. Al ser una extensión coordinada, se apoya de forma directa en _dom para la selección e iteración de los nodos declarados en el HTML, y en _events para vincular los disparadores físicos del ciclo de vida del DOM.


Sintaxis de Registro:

_handlers(handlersMap, shortcutsMap?).start(startNode?);

Argumentos del Constructor:

  • handlersMap (Object): Colección de funciones donde cada clave representa el identificador lógico del handler.

  • shortcutsMap (Object): Opcional. Diccionario de atajos para agrupar múltiples identificadores de handlers bajo un alias común, permitiendo ejecuciones secuenciales parametrizadas de forma ágil.

Método de Arranque (.start()):

  • startNode (Node/String): Opcional. Limita la búsqueda de selectores declarativos al subárbol del nodo o resultado del selector CSS especificado. Si se omite, realiza una búsqueda global en el DOM utilizando el selector de primer nivel > [data-e-handler].

  • Nota de integración: Debido al patrón de envoltura de métodos del framework Estructura (adjust_method), los argumentos pasados al despachador inicial se inyectan como primer parámetro de los métodos resueltos. Por ello, la firma interna de ejecución del método es start(args, start_node), aunque su llamada externa se efectúa pasando directamente el nodo de inicio opcional.

2. Sintaxis Declarativa en HTML (Atributos Dataset)

La declaración de comportamiento se define directamente sobre los elementos HTML mediante atributos de datos (data-*):


  • data-e-handler (String): Lista de handlers (o atajos) separados por espacios o comas que procesarán el elemento. Admite segmentación por sub-identificadores mediante puntos (.) o barras verticales (|) (ej. peticion.filtrada).

  • data-e-handler-id (String): Requerido. Identificador único de instancia para el elemento. El motor remueve automáticamente los espacios en blanco de este atributo (ej. "btn - registro" se almacena en memoria como "btn-registro"). Permite mantener un estado aislado en memoria para ese nodo específico sin interferir con otros elementos que utilicen el mismo handler.

  • data-e-handler-event (String): Opcional. Evento del DOM que disparará la ejecución del flujo (ej. "click", "submit", "dblclick.test").

  • data-e-handler-middleware (Boolean): Opcional. Si está presente, el flujo de ejecución principal del elemento operará en modo Middleware, inyectando un callback de continuación (next) entre cada función del flujo.

Enlaces de Ciclo de Vida Dinámicos (Atributos Específicos por Handler):

Para cada handler declarado en el atributo data-e-handler, el motor habilita propiedades adicionales basadas en su nombre formateado. El sistema procesa de forma automática los nombres kebab-case mediante camelCase (ej. un handler denominado mi-peticion habilitará atributos del tipo data-e-mi-peticion-* correspondientes a propiedades dataset de JavaScript):


  • data-e-[nombre-handler]-middleware: Opcional. Si está presente, indica que el flujo específico de las secuencias conectadas o de éxito/error de este handler operará bajo el modo de middleware.

  • data-e-[nombre-handler]-connect: Lista de handlers adicionales que se inicializarán y conectarán en fase de carga.

  • data-e-[nombre-handler]-success: Lista de handlers que se ejecutarán automáticamente al asignar un estado de éxito al handler actual.

  • data-e-[nombre-handler]-error: Lista de handlers que se ejecutarán automáticamente al asignar un estado de error al handler actual.

3. El Contexto de Ejecución (this)

Cuando un handler es invocado, su contexto de ejecución (this) es enlazado a un objeto de estado exclusivo mapeado mediante su identificador único (id). Este contexto proporciona los siguientes accesos y propiedades de control de flujo:


  • this.liveElement (Node): Referencia directa al elemento activo en el DOM.

  • this.initialElement (Node): Clon inmutable del elemento en su estado original de registro. Útil para consultar configuraciones o atributos sin mutaciones añadidas por flujos intermedios.

  • this.ready (Boolean): Rastreador interno que indica si el handler está listo para recibir operaciones de conexión. Si se re-registra un elemento cuyo ready estaba establecido en false, el sistema reinicia automáticamente su estado a true.

  • this.success (Cualquier tipo): Propiedad Reactiva (Setter). No es una función. Al asignarle un valor (ej. this.success = datos), se dispara de manera interna la secuencia de handlers declarada en el atributo respectivo (-success), propagando los datos transmitidos.

  • this.error (Cualquier tipo): Propiedad Reactiva (Setter). No es una función. Al asignarle un valor (ej. this.error = fallo), se dispara de manera interna la secuencia de handlers de error asociada (-error).

  • this.connect(state, data, ids?) (Function): Permite propagar estados y datos estructurados hacia los handlers conectados de manera cruzada. El parámetro de destino ids puede ser provisto como un string individual o un arreglo de strings.

    Restricción de seguridad: No está permitido transmitir estados hacia claves reservadas del contexto. Si el argumento state coincide con "liveElement", "initialElement", "connect" o "ready", la operación se cancelará emitiendo una advertencia en la consola.

4. Modos de Ejecución y Firmas de Argumentos

El motor proporciona firmas de argumentos consistentes que varían según el modo de ejecución (estándar o middleware) y el origen del desencadenante:


A. Modo Secuencial (Estándar)

Los controladores se ejecutan de manera directa e independiente uno tras otro. Cada función opera sobre su contexto de instancia aislado. Las asignaciones directas a las propiedades reactivas propagan los flujos en un esquema unidireccional.


  • Manejadores de Evento DOM: Reciben el evento nativo o el desencadenante inicial. 
    function miHandler(event) {
    // event: Objeto Event del DOM o trigger de activación
    console.log("Evento:", event);
}

  • Manejadores de Éxito / Error: Reciben de manera directa el dato asignado al setter reactivo. 
    function miHandlerExito(data) {
    // data: El valor asignado a this.success o this.error
    console.log("Datos recibidos:", data);
}

B. Modo Middleware

Activado mediante la presencia de data-e-handler-middleware o por la configuración específica del handler. Modifica el flujo para crear una cadena secuencial asíncrona donde cada handler puede interceptar, alterar o detener la continuación del proceso. El acumulador de datos que se propaga por la cadena (data) se inicializa como un objeto limpio sin prototipo (Object.create(null)).


  • Middlewares de Evento DOM: Reciben el evento, el acumulador de datos y la función de continuación. 
    function miMiddleware(event, data, next) {
    data.timestamp = Date.now();
    return next(data); // Continuación explícita del flujo
}

  • Middlewares de Éxito o Error: Reciben el valor asignado de origen (payload), el acumulador de datos interno y la función de continuación. 
    function miMiddlewareDeCiclo(payload, data, next) {
    // payload: El valor asignado a la propiedad reactiva
    // data: El objeto acumulador del flujo
    data.resultado = payload;
    return next(data);
}

Si un paso en la cadena de middlewares omite llamar a la función next(data) (o no retorna su invocación), la ejecución posterior se detiene por completo, actuando como un mecanismo de validación de seguridad o control de flujo asíncrono.


5. Ejemplos Prácticos de Implementación

Estructuración Declarativa en HTML con Conexión Cruzada:

<button id="accion"
	data-e-handler="logger, validador, peticion"
	data-e-handler-id="btn-registro"
	data-e-handler-event="click"
	data-e-handler-middleware
	data-e-peticion-connect="formulario"
	data-e-peticion-success="limpiarFormulario"
	data-e-peticion-error="mostrarAlerta">
	Enviar Registro
</button>

<form id="registro" data-e-handler="formulario" data-e-handler-id="form-usuario">
	<!-- Campos del formulario -->
</form>

Definición y Enlace de Flujos en JavaScript:

// Definición de manejadores de lógica
_handlers({
	logger: function(event, data, next) {
		console.log("Evento click registrado en ID:", this.liveElement.id);
		return next(data);
	},

	validador: function(event, data, next) {
		var esValido = true; // Flujo de validación interna
		if (esValido) {
			data.formularioOk = true;
			return next(data);
		}
		// Al no llamar a next(), detenemos la cadena de ejecución
		console.warn("Validación fallida. Flujo cancelado.");
	},

	peticion: function(event, data, next) {
		var self = this;
		// Simulación de proceso asíncrono
		setTimeout(function() {
			var exito = true;
			if (exito) {
				// Modifica reactivamente el estado de otra instancia conectada
				self.connect('success', { limpiado: true }, 'form-usuario');
				self.success = { codigo: 200 };
			} else {
				self.error = { mensaje: "Error de conexión" };
			}
		}, 1000);
		return next(data);
	},

	formulario: function(event) {
		console.log("Formulario inicializado o activado de forma externa");
	},

	limpiarFormulario: function(data) {
		console.log("Completado con éxito. Limpiando interfaz...", data);
	},

	mostrarAlerta: function(data) {
		console.error("Hubo un error en la secuencia:", data.mensaje);
	}
}, {
	// Definición de atajos opcionales
	"flujo-completo": ["logger", "validador", "peticion"]
}).start();

6. Características Técnicas de la Implementación

Aislamiento de Instancia Seguro: Cada handler opera sobre un contexto (this[id]) creado con herencia limpia mediante Object.create(null), previniendo colisiones de datos con las propiedades del prototipo global de JavaScript.


Control Reactivo mediante Setters: El motor utiliza descriptores de acceso dinámicos (Object.defineProperty) para mapear las claves de control de ciclo de vida (ready, success, error). La asignación de valores a estas propiedades actúa como un disparador automático que procesa y propaga las secuencias definidas.


Soporte para Sub-identificadores: El sistema analiza y segmenta las declaraciones de handlers utilizando la expresión regular /[\|\.]+/. Al invocar flujos directos mediante callbacks, estos sub-identificadores adicionales se propagan de manera estructurada en un arreglo, permitiendo la ejecución selectiva sobre instancias específicas (ej. handler.instanciaId).


Normalización Automatizada de Nombres: La extensión integra una rutina de formateo (_capitalizeAndCamelCase) que unifica el uso de guiones medios en el marcado HTML (kebab-case) y mapea de manera precisa las propiedades dentro del diccionario de datos (camelCase) del navegador, coincidiendo con la transformación estándar del motor de datasets.


Persistencia del Nodo de Configuración: Mediante la integración de copias inmutables del nodo original (cloneNode) en la propiedad initialElement, los programadores mantienen la capacidad de auditar la parametrización de inicio del marcado HTML, independientemente de las manipulaciones directas sobre el nodo activo del DOM (liveElement).


Análisis de Exclusiones de Espacios en Identificadores: El sistema sanea los atributos de identificación única del control declarativo, removiendo caracteres de espaciado mediante expresiones regulares para garantizar correspondencias y prevenir accesos indexados anómalos en memoria.


Protección contra Colisiones de Estado: El sistema valida rigurosamente las llamadas a connect para impedir la mutación remota de propiedades reservadas del ciclo de vida interno (liveElement, initialElement, connect, ready), previniendo comportamientos inconsistentes o rupturas en el flujo de ejecución.
