DOM

Description

Manipulates the DOM. Runs queries, and gets and sets properties (including style and dataset) in a unified way, through CSS selectors (DOMQuery), single nodes (Node), or node lists (Nodes).

Library: estructura.dom.js

Compatibility: ES5+

Status: RC2

License: AGPL v3

Import:
<!-- EXTENSION: Estructura / DOM -->
<script src="https://estructura.okzgn.com/extensions/dom/estructura.dom.js"></script>

Documentation

1. Basic usage

Select DOM elements with a CSS selector in a String that starts with > (DOMQuery), a node (Node), or a list of nodes (NodeList or HTMLCollection). The > prefix tells the library that the text is a CSS selector that it should use to search the document. The search is repeated on every method call, so it reflects the current state of the document.

  • These are not valid targets: a String without >, null, document, window, or an array. The result has no methods, and calling one throws a TypeError.
  • When a node is passed directly, any element is recognized (HTML, SVG such as <path>, custom elements…), as well as text and comment nodes.
// Select elements and apply changes
_dom('> .my-class').set('id', 'new-id');
_dom('> div').style('backgroundColor', 'red');

// Get values (an array, with one value per element)
var ids = _dom('> #my_element_with_id').get('id');

// With Node
_dom(document.body).each(function(element, index){ console.log('Body:', element); });

// With Nodes
var classes = _dom(document.getElementsByClassName('myClass')).get('className');

2. Main methods

Chaining: .each() and writes (.set(), and .style()/.data() when they receive value) return the same object, so they can be chained. Reads (.get(), and .style()/.data() without value) return an array (Array) with one value per element. .set() without value (or with undefined) also behaves as a read and returns an array.

_dom('> .box')
	.set('title', 'Box')
	.style('color', 'blue')
	.data('state', 'active')
	.each(function(element, index){ console.log(index, element); });

.each(callback)

Iterates over each selected DOM element. The callback receives the element and its index. Returns the same object for chaining.

_dom('> li').each(function(element, index){
	console.log('Element ' + index + ':', element);
});

.get(property)

Gets the value of a property from all the selected DOM elements. Supports nested access with dots. Returns an array (Array) with the results. style.* paths follow the same read rule as .style().

var values = _dom('> input').get('value'); // One value per input
var firstValue = values[0];
var classes = _dom('> div').get('className');
var styles = _dom('> main').get('style.color');

.set(property, value)

Sets the value of a property on all the selected DOM elements. Supports nested access with dots. The value first goes through _dom.sanitize (see Sanitization). Returns the same object for chaining.

_dom('> input').set('value', 'Hello World');
_dom('> body').set('style.background', 'yellow');

.style(property, value)

Manipulates CSS styles. With value, it applies the value as an inline style and returns the same object for chaining. Without value, it returns an array (Array) with each element’s inline style; if the inline style is empty, the computed value (getComputedStyle) is used. It accepts property names in camelCase (e.g., backgroundColor) and in kebab-case (e.g., background-color). CSS custom properties (--my-variable) are not supported: use style.setProperty() and getPropertyValue() inside .each().

_dom('> .box').style('color', 'blue');
var colors = _dom('> .box').style('color'); // Array: inline style or, if it is empty, the computed one

.data(property, value)

Manipulates the dataset. Lets you read and write dataset properties with or without the data- prefix; hyphenated names are automatically converted to camelCase. With value, it writes (the value is stored as text, just as in dataset) and returns the same object for chaining. Without value, it returns an array (Array) with each element’s value.

_dom('> div').data('user-id', '456');
var ids = _dom('> div').data('user-id'); // Array with the value of each div

3. Sanitization

Every write with .set() goes through the _dom.sanitize(value, ctx) function before it is assigned, where ctx is { type: 'property', name, element } and name is the final key of the path. The function returns the value that is finally written. Writes with .style()/.data() (or style.*/dataset.* paths) do not go through it.

What is filtered by default:

  • In URL properties (href, src, action, formaction, xlink:href, poster, cite, background), the javascript: and vbscript: schemes are neutralized: '' is written and a console.warn is emitted.
  • data: is allowed only in src and poster, and only for data:image/, data:video/, or data:audio/; otherwise, it is neutralized in the same way.
  • To compare the scheme (without changing the value that is written), spaces and control characters are removed and the text is lowercased, since browsers accept variants such as java\tscript:.

What is not filtered, and why: textContent (already safe), value and checked, boolean attributes, className, id, style.*, dataset.*, and aria-*, because they do not execute code. HTML sinks (innerHTML, outerHTML, srcdoc) pass through unchanged: filtering HTML reliably requires a full parser, so that is left to a specialized library.

Replace or extend: assign your own function to _dom.sanitize. To keep the default rules, save the original and call it from the new one. Assigning a function that returns value unchanged disables the filter.

// Connect DOMPurify (loaded earlier on the page) for the HTML sinks,
// keeping the default rules
var sanitizeDefault = _dom.sanitize;
var htmlSinks = { innerHTML: true, outerHTML: true, srcdoc: true };

_dom.sanitize = function(value, ctx){
	if(htmlSinks[ctx.name]){ return DOMPurify.sanitize(String(value)); }
	return sanitizeDefault(value, ctx);
};

var userHtml = '<img src="x" onerror="alert(1)">';
_dom('> #content').set('innerHTML', userHtml); // Writes the image without onerror
_dom('> a').set('href', 'javascript:alert(1)'); // Writes '' and logs a warning to the console

4. Technical details

Computed style only when needed: when a style is read, the inline value is returned first, and getComputedStyle is called only when that value is empty.

Path normalization: all spaces in the path are removed, as are dots at the start or end (' style.color. ' is equivalent to 'style.color').

Nonexistent paths: if an intermediate segment of the path does not exist or has a falsy value (such as null, 0, or ''), a read returns undefined for that element and a write does nothing.

Errors: they do not reach the caller as exceptions. The Estructura core catches them and shows them in the console with a delay of up to one second, and the method returns the methods object instead of an array. They occur with an empty property (including one that becomes empty once its name is cleaned up, such as .data('data-')) or one that is not a String, with an invalid CSS selector, with a style/dataset path that does not have exactly one more level ('style.color' is valid; 'style' and 'style.a.b' are not), and when the .each() callback throws an error, which also stops the iteration.
