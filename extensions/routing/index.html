Routing

Descripción

Gestiona la navegación y el enrutamiento en el cliente para aplicaciones de una sola página (SPA), mediante la API History del navegador. Admite parámetros dinámicos y opcionales, ordena las rutas por especificidad, encadena callbacks síncronos o asíncronos con next(), analiza los parámetros de consulta (query strings) y permite registrar callbacks de error.

Librería: estructura.routing.js

Compatibilidad: ES6+

Estado: RC2

Licencia: AGPL v3

Importación:
<!-- EXTENSIÓN: Estructura / Routing -->
<script src="https://estructura.okzgn.com/extensions/routing/estructura.routing.js"></script>

Documentación

1. Inicialización y ciclo de vida

El enrutamiento se gestiona a través de la instancia global _routing, que expone los métodos de configuración y de control del ciclo de vida.

  • _routing.start(options?): activa el enrutador y empieza a escuchar eventos en la ventana (window). Retorna false si lo arranca y true si ya estaba en marcha (en ese caso no hace nada). Opciones de configuración:
    • click (Boolean): intercepta los clics en enlaces (<a>) del mismo origen y navega sin recargar la página (por defecto, true). Ver Filtrado de interceptación en Características técnicas.
    • popstate (Boolean): escucha los cambios de historial cuando el usuario retrocede o avanza en el navegador (por defecto, true).
    • dispatch (Boolean): al arrancar, ejecuta las rutas que coinciden con la dirección actual, sin escribir en el historial (por defecto, true). Se ejecuta en el momento, así que registre las rutas antes de arrancar.
  • _routing.stop(): detiene el enrutador y elimina sus listeners globales (click y popstate). Retorna true si lo detiene y false si no estaba en marcha.
  • _routing.base(path?): sin argumentos, retorna la ruta base (prefijo) del enrutamiento; con un String que empiece por /, la establece (ej. /app). Se elimina la barra final (/app/ queda como /app). La base solo se recorta de la dirección en un límite de segmento: /app coincide con /app y /app/perfil, pero no con /application.

Atajos:

_routing();                    // Arranca, como _routing.start()
_routing({ dispatch: false }); // Arranca con opciones, como _routing.start({...})
_routing('/perfil');           // Navega, como _routing.show('/perfil')

A diferencia de los métodos, los atajos no retornan su resultado (por ejemplo, el contexto de show()), y un error que se produzca dentro se muestra en la consola con hasta un segundo de retraso, en lugar de lanzarse.

2. Registro de rutas

Las rutas se declaran llamando a la función global _routing con un patrón y uno o varios callbacks. Cada callback recibe el contexto (ctx) y la función next, que da paso al siguiente callback; puede llamarse más tarde, por ejemplo tras una operación asíncrona. Registrar de nuevo el mismo patrón reemplaza sus callbacks.

Orden de ejecución: al navegar, se ejecutan todas las rutas cuyo patrón coincide, de la más específica a la menos específica, y dentro de cada ruta sus callbacks en el orden registrado. La ejecución solo avanza mientras cada callback llame a next(); si uno no lo llama, la cadena se detiene ahí.

_routing(fn) registra el patrón *, que coincide con cualquier ruta y tiene la prioridad más baja: se ejecuta después de las rutas más específicas, y solo si estas llaman a next().

Sintaxis de registro:

var sesion = { activa: true };

// Middleware: continúa con next() o redirige
function authMiddleware(ctx, next){
	if(!sesion.activa){
		_routing.redirect('/login');
		return;
	}
	next();
}

// Ruta con varios callbacks
_routing('/perfil', authMiddleware, function(ctx, next){
	console.log('Ruta de perfil cargada');
	next(); // Sin esta llamada, el callback de '*' no se ejecutaría
});

// Callback para todas las rutas (patrón '*', se ejecuta al final)
_routing(function(ctx, next){
	console.log('Log para:', ctx.pathname);
	next();
});

3. Parámetros y patrones

Los patrones declarados se traducen a expresiones regulares, y los segmentos variables se guardan en ctx.params. Los valores se decodifican (decodeURIComponent); una secuencia mal formada (como un % suelto) se conserva sin decodificar en lugar de lanzar un error.

  • Parámetros requeridos (:param): capturan un segmento de texto entre barras. 
    _routing('/usuario/:id', function(ctx){ console.log(ctx.params.id); });
  • Parámetros opcionales (:param?): el segmento puede omitirse (/blog y /blog/noticias coinciden); si falta, el parámetro es undefined. 
    _routing('/blog/:categoria?', function(ctx){ console.log(ctx.params.categoria); });
  • Comodín (*): captura cualquier subruta posterior y la asigna a ctx.params.wildcard. Exige la barra previa: /archivos/* coincide con /archivos/a/b, pero no con /archivos. 
    _routing('/archivos/*', function(ctx){ console.log(ctx.params.wildcard); });

4. Objeto de contexto

Cada callback registrado recibe como primer argumento un objeto de contexto con la información de la navegación actual.

Propiedades del contexto:

  • ctx.canonicalPath (String): la ruta completa, incluida la ruta base, los parámetros de búsqueda y el fragmento (hash).
  • ctx.path (String): la ruta sin el prefijo de la ruta base (incluye búsqueda y hash).
  • ctx.pathname (String): la ruta sin base, sin parámetros de búsqueda, sin hash y sin barra final. Es la que se compara con los patrones; no se decodifica (%20 se mantiene).
  • ctx.querystring (String): la cadena de consulta sin el símbolo de interrogación (?).
  • ctx.state (Object): copia del estado pasado a show() o replace() (o del guardado en la entrada del historial, al retroceder o avanzar), a la que la librería añade path (igual que ctx.canonicalPath) y cleanPath (igual que ctx.path); si el estado ya traía otros valores en esas claves, se sobrescriben con un aviso en la consola. Puede contener funciones o nodos del DOM: se conservan por referencia en ctx.state. Como la API History solo guarda datos serializables, en ese caso la entrada del historial guarda únicamente path y cleanPath y se emite un aviso en la consola.
  • ctx.params (Object): parámetros extraídos del patrón de la ruta actual (ej. { id: "42" }).
  • ctx.query (Object): parámetros de consulta analizados y decodificados (+ se convierte en espacio). Cada par se divide por el primer =, así que el valor puede contener = (?t=abc== da 'abc=='). Las claves repetidas se acumulan en un array (ej. ?filtro=a&filtro=b se convierte en { filtro: ["a", "b"] }). Como en ctx.params, una secuencia mal formada se conserva sin decodificar.
  • ctx.hash (String): el fragmento de la URL sin el carácter inicial (#).
  • ctx.routePath (String): el patrón registrado de la ruta que se está ejecutando.

Métodos del contexto:

  • ctx.pushState(): añade al historial del navegador una entrada con ctx.state y ctx.canonicalPath.
  • ctx.save(): reemplaza la entrada actual del historial con ctx.state (útil tras modificarlo).

5. Navegación y redirecciones

Permite navegar desde código, controlando la escritura en el historial y la ejecución de las rutas. Ambos métodos retornan el contexto creado. state es un objeto opcional; cualquier otro valor se sustituye por {}. Si path empieza por / y no incluye la ruta base, se le antepone (con base /app, show('/perfil') navega a /app/perfil); una ruta sin / inicial se resuelve desde la raíz del origen y no recibe la base.

  • _routing.show(path, state?, dispatch?, push?): navega a la ruta indicada añadiendo una entrada al historial. dispatch y push son true por defecto; con false se desactiva, respectivamente, la ejecución de las rutas o la escritura en el historial.
  • _routing.replace(path, state?, dispatch?, replace?): navega a la ruta indicada reemplazando la entrada actual del historial. dispatch y replace son true por defecto; con false se desactiva, respectivamente, la ejecución de las rutas o la escritura en el historial.
  • _routing.redirect(from, to) o _routing.redirect(to): con dos argumentos registra una regla de redirección (una ruta from que redirige a to); con uno, redirige a to. En ambos casos la redirección se aplica con replace() en una microtarea, después de que termine el callback actual. 
    // Regla de redirección
_routing.redirect('/inicio', '/');

// Redirección desde un callback
_routing('/obsoleto', function(ctx){
	_routing.redirect('/');
});

6. Errores y desvinculación

Permite gestionar los fallos durante la ejecución de los callbacks y eliminar rutas registradas.

  • _routing.onError(callback?): registra un callback global que recibe (error, ctx) cuando un callback de ruta lanza un error de forma síncrona (no captura rechazos de promesas); la cadena de callbacks se detiene ahí. Si no hay ninguno registrado, el error se relanza. Sin argumentos, retorna una copia del array de callbacks de error registrados.
  • _routing.offError(callback?): elimina un callback de error concreto, o todos si se omite el argumento.
  • _routing.off(path?, callback?): elimina un callback de una ruta, una ruta completa o, sin argumentos, todas las rutas registradas. path es el patrón tal como se registró. Retorna true si elimina algo y false en caso contrario (sin argumentos, siempre true).

7. Características técnicas

Resolución por especificidad: los patrones se comparan segmento a segmento, de izquierda a derecha, con este orden de prioridad: segmento estático, parámetro requerido (:id), segmento ausente (el patrón ya no tiene más), parámetro opcional (:id?) y comodín (*). Así, en la dirección /blog se ejecuta /blog antes que /blog/:categoria?; en /blog/5, /blog/:id antes que /blog/:categoria?; y en /es, /:idioma? antes que *. La ruta raíz / cuenta como estática y va antes que *. Con la misma puntuación, se respeta el orden de registro.

Copia del estado: el estado de cada navegación se copia en profundidad con structuredClone. Si no está disponible, o el estado contiene valores no serializables, se usa una copia recursiva propia que admite Map, Set, Date, RegExp, ArrayBuffer y arrays tipados, y conserva por referencia funciones y nodos del DOM.

Filtrado de interceptación: con click activo, el enrutador no intercepta los enlaces con target distinto de _self, con el atributo download, con rel="external" (valor exacto: rel="external noopener" sí se intercepta), con el atributo data-e-routing-excluded o sin href; tampoco los de otro origen, los que usan los esquemas mailto:, tel:, sms:, javascript: o data:, los clics con teclas modificadoras (Ctrl, Shift, Alt o Meta/Command), con un botón distinto del principal o cuyo evento ya fue cancelado (preventDefault()). Los href interceptados se resuelven desde la raíz del origen (no desde la página actual) y, si no empiezan por la ruta base, se les antepone. Las anclas internas (href="#seccion") también se interceptan: navegan a la raíz de la base con ese hash y el navegador no se desplaza hasta la sección; añádales data-e-routing-excluded para conservar el comportamiento nativo.

Redirecciones en microtareas: redirect() se aplica en una microtarea (queueMicrotask o, si no existe, MutationObserver; como último recurso, setTimeout), una vez que termina el código que la llamó.
