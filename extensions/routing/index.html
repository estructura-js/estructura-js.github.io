Routing

Description

Manages client-side navigation and routing for single-page applications (SPAs) through the browser’s History API. It supports dynamic and optional parameters, sorts routes by specificity, chains synchronous or asynchronous callbacks with next(), parses query parameters, and lets you register error callbacks.

Library: estructura.routing.js

Compatibility: ES6+

Status: RC2

License: AGPL v3

Import:
<!-- EXTENSION: Estructura / Routing -->

Documentation

1. Initialization and lifecycle

Routing is managed through the global _routing function, which exposes the configuration and lifecycle control methods.

  • _routing.start(options?): activates the router and starts listening for events on window. Returns false if it starts the router and true if it was already running (in which case it does nothing). Configuration options:
    • click (Boolean): intercepts clicks on same-origin links (<a>) and navigates without reloading the page (default: true). See Interception filtering in Technical details.
    • popstate (Boolean): listens for history changes when the user goes back or forward in the browser (default: true).
    • dispatch (Boolean): on start, runs the routes that match the current URL, without writing to the history (default: true). This happens immediately, so register the routes before starting.
  • _routing.stop(): stops the router and removes its global listeners (click and popstate). Returns true if it stops the router and false if it was not running.
  • _routing.base(path?): without arguments, returns the routing base path (prefix); with a String that starts with /, sets it (e.g., /app). The trailing slash is removed (/app/ becomes /app). The base is trimmed from the URL only at a segment boundary: /app matches /app and /app/profile, but not /application.

Shortcuts:

_routing();                    // Starts, like _routing.start()
_routing({ dispatch: false }); // Starts with options, like _routing.start({...})
_routing('/profile');          // Navigates, like _routing.show('/profile')

Unlike the methods, the shortcuts do not return their result (for example, the context from show()), and an error that occurs inside them is shown in the console with a delay of up to one second instead of being thrown.

2. Registering routes

Routes are declared by calling the global _routing function with a pattern and one or more callbacks. Each callback receives the context (ctx) and the next function, which passes control to the next callback; it can be called later, for example after an asynchronous operation. Registering the same pattern again replaces its callbacks.

Execution order: when navigating, all the routes whose pattern matches are run, from the most specific to the least specific, and within each route its callbacks run in the order they were registered. Execution only moves forward as long as each callback calls next(); if one does not call it, the chain stops there.

_routing(fn) registers the * pattern, which matches any path and has the lowest priority: it runs after the more specific routes, and only if they call next().

Registration syntax:

var session = { active: true };

// Middleware: continues with next() or redirects
function authMiddleware(ctx, next){
	if(!session.active){
		_routing.redirect('/login');
		return;
	}
	next();
}

// Route with several callbacks
_routing('/profile', authMiddleware, function(ctx, next){
	console.log('Profile route loaded');
	next(); // Without this call, the '*' callback would not run
});

// Callback for every path ('*' pattern, runs last)
_routing(function(ctx, next){
	console.log('Log for:', ctx.pathname);
	next();
});

3. Parameters and patterns

Declared patterns are converted into regular expressions, and the variable segments are stored in ctx.params. The values are decoded (decodeURIComponent); a malformed sequence (such as a stray %) is kept undecoded instead of throwing an error.

  • Required parameters (:param): capture a text segment between slashes. 
    _routing('/user/:id', function(ctx){ console.log(ctx.params.id); });
  • Optional parameters (:param?): the segment can be omitted (/blog and /blog/news both match); if it is missing, the parameter is undefined. 
    _routing('/blog/:category?', function(ctx){ console.log(ctx.params.category); });
  • Wildcard (*): captures any subpath that follows and assigns it to ctx.params.wildcard. It requires the preceding slash: /files/* matches /files/a/b, but not /files. 
    _routing('/files/*', function(ctx){ console.log(ctx.params.wildcard); });

4. Context object

Each registered callback receives, as its first argument, a context object with the information about the current navigation.

Context properties:

  • ctx.canonicalPath (String): the full path, including the base path, the search parameters, and the fragment (hash).
  • ctx.path (String): the path without the base path prefix (it includes the search and the hash).
  • ctx.pathname (String): the path without the base, search parameters, hash, or trailing slash. This is the value matched against the patterns; it is not decoded (%20 stays as is).
  • ctx.querystring (String): the query string without the question mark (?).
  • ctx.state (Object): a copy of the state passed to show() or replace() (or of the state saved in the history entry, when going back or forward), to which the library adds path (same as ctx.canonicalPath) and cleanPath (same as ctx.path); if the state already had other values in those keys, they are overwritten and a warning is logged to the console. It can contain functions or DOM nodes: they are kept by reference in ctx.state. Since the History API only stores serializable data, in that case the history entry stores only path and cleanPath, and a warning is logged to the console.
  • ctx.params (Object): parameters extracted from the current route’s pattern (e.g., { id: "42" }).
  • ctx.query (Object): parsed and decoded query parameters (+ becomes a space). Each pair is split at the first =, so the value can contain = (?t=abc== gives 'abc=='). Repeated keys are collected into an array (e.g., ?filter=a&filter=b becomes { filter: ["a", "b"] }). As in ctx.params, a malformed sequence is kept undecoded.
  • ctx.hash (String): the URL fragment without the leading character (#).
  • ctx.routePath (String): the registered pattern of the route that is running.

Context methods:

  • ctx.pushState(): adds an entry with ctx.state and ctx.canonicalPath to the browser history.
  • ctx.save(): replaces the current history entry with ctx.state (useful after modifying it).

5. Navigation and redirects

Lets you navigate programmatically, controlling writes to the history and the execution of routes. show() and replace() return the created context. state is an optional object; any other value is replaced with {}. If path starts with / and does not include the base path, the base is prepended (with base /app, show('/profile') navigates to /app/profile); a path without a leading / is resolved from the origin’s root and does not get the base.

  • _routing.show(path, state?, dispatch?, push?): navigates to the given path, adding an entry to the history. dispatch and push are true by default; setting either one to false disables route execution or the history write, respectively.
  • _routing.replace(path, state?, dispatch?, replace?): navigates to the given path, replacing the current history entry. dispatch and replace are true by default; setting either one to false disables route execution or the history write, respectively.
  • _routing.redirect(from, to) or _routing.redirect(to): with two arguments, registers a redirect rule (a from route that redirects to to); with one, redirects to to. In both cases, the redirect is applied with replace() in a microtask, after the current callback finishes. The rule is registered like any other route, with a single callback that performs the redirect. Registering it replaces any callbacks already registered for the same pattern (and registering that pattern later replaces the rule). Since its callback does not call next(), the routes that would run after it at that URL do not run: less specific ones, such as *, and equally specific ones registered later. 
    // Redirect rule
_routing.redirect('/home', '/');

// Redirect from a callback
_routing('/old', function(ctx){
	_routing.redirect('/');
});

6. Errors and unbinding

Lets you handle failures during callback execution and remove registered routes.

  • _routing.onError(callback?): registers a global callback that receives (error, ctx) when a route callback throws an error synchronously (it does not catch promise rejections); the callback chain stops there. If none is registered, the error is rethrown. Without arguments, returns a copy of the array of registered error callbacks.
  • _routing.offError(callback?): removes a specific error callback, or all of them if the argument is omitted.
  • _routing.off(path?, callback?): removes a callback from a route, a whole route, or, without arguments, all registered routes. path is the pattern exactly as it was registered. Returns true if it removes something and false otherwise (without arguments, always true).

7. Technical details

Resolution by specificity: patterns are compared segment by segment, from left to right, with this priority order: static segment, required parameter (:id), missing segment (the pattern has no more segments), optional parameter (:id?), and wildcard (*). So, for the URL /blog, /blog runs before /blog/:category?; for /blog/5, /blog/:id runs before /blog/:category?; and for /en, /:language? runs before *. The root route / counts as static and goes before *. Patterns with the same score run in registration order.

State copy: the state of each navigation is deep-copied with structuredClone. If it is not available, or the state contains non-serializable values, the library uses its own recursive copy, which supports Map, Set, Date, RegExp, ArrayBuffer, and typed arrays, and keeps functions and DOM nodes by reference.

Interception filtering: with click active, the router does not intercept links with a target other than _self, with the download attribute, with rel="external" (exact match only: rel="external noopener" is still intercepted), with the data-e-routing-excluded attribute, or without href; nor does it intercept links to another origin, links that use the mailto:, tel:, sms:, javascript:, or data: schemes, clicks with modifier keys (Ctrl, Shift, Alt, or Meta/Command), clicks with a button other than the primary one, or clicks whose event was already canceled (preventDefault()). Intercepted href values are resolved from the origin’s root (not from the current page) and, if they do not start with the base path, the base is prepended. In-page anchors (href="#section") are also intercepted: they navigate to the root of the base with that hash, and the browser does not scroll to the section; add data-e-routing-excluded to them to keep the native behavior.

Redirects in microtasks: redirect() is applied in a microtask (queueMicrotask or, if that does not exist, MutationObserver; as a last resort, setTimeout), once the code that called it finishes.
