Components

Descripción

Carga componentes de interfaz formados por archivos HTML, CSS y JS, de forma asíncrona y coordinada. La librería gestiona el ciclo de vida de cada componente, el orden de carga y las dependencias declaradas en el DOM, las colisiones de IDs y los componentes de contingencia ante fallos de carga o de red.

Librería: estructura.components.js

Compatibilidad: ES5/ES6+

Estado: RC3

Licencia: AGPL v3

Dependencia obligatoria: estructura.http.js (HTTP, documentación). El objeto global _http debe estar disponible antes de cargar Components; si no lo está, la librería lanza una excepción al cargarse.

Importación:
<!-- DEPENDENCIA: Estructura / HTTP -->
<script src="https://estructura.okzgn.com/extensions/http/estructura.http.js"></script>

<!-- EXTENSIÓN: Estructura / Components -->
<script src="https://estructura.okzgn.com/extensions/components/estructura.components.js"></script>

Documentación

Inicio rápido

Cree una carpeta por componente con los archivos .css, .html y .js, indique la carpeta base con origin e inicialice el elemento:

<!-- Carga ./componentes/saludo/.css, ./componentes/saludo/.html y ./componentes/saludo/.js -->
<div id="saludo" data-e-component="saludo">Cargando…</div>

<script>
_components({ origin: './componentes/' });
_components(document.getElementById('saludo'));
</script>

1. Inicialización y configuración

La librería expone la función _components. Su valor de retorno depende del argumento:

  • Configuración global: Con un objeto plano, actualiza las opciones globales y devuelve un objeto con el método .config(), que devuelve las opciones activas.
  • Inicialización de elementos: Con un nodo del DOM, inicia el componente o coordinador declarado en él y devuelve un objeto con el método .ref(), que devuelve su instancia (ver sección 4).

Configuración global

var configActiva = _components({
    // Carpeta base donde se buscan los componentes
    origin: './src/components/',

    // Tiempo máximo de cada petición, en milisegundos (10 s)
    timeout: 10000,

    // Si es true, ejecuta _components.autoScan() (false por defecto)
    autoScan: false,

    // Nombre de archivo de cada recurso dentro de la carpeta del componente
    files: {
        css: '.css',
        html: '.html',
        js: '.js'
    },

    // Lista blanca opcional de orígenes externos (null = sin restricción)
    allowedOrigins: ['https://cdn.example.com']
}).config();

Propiedad files (Object): Define el nombre de archivo de cada tipo de recurso (css, html, js). El valor se añade tal cual a la ruta de la carpeta del componente, así que por defecto se piden archivos llamados literalmente .css, .html y .js. Por ejemplo, con origin: './components-origin/' y data-e-component="test", la librería pide ./components-origin/test/.css, ./components-origin/test/.html y ./components-origin/test/.js. Con files: { css: 'estilos.css', html: 'vista.html', js: 'script.js' }, pediría ./components-origin/test/estilos.css, etc. Si falta un tipo en files, se usa '.' + tipo. También se puede indicar por instancia en el segundo argumento de _components(elemento, opciones); el componente de contingencia de esa instancia usa el mismo files (y también el timeout y el origin pasados como opciones).

Propiedad allowedOrigins (Array|null): Lista blanca opcional de orígenes desde los que se permite descargar recursos (ej. 'https://cdn.example.com'). Por defecto es null y no se aplica ninguna restricción. Cada URL se resuelve de forma absoluta respecto a document.baseURI antes de la petición y el mismo origen de la página (location.origin) siempre está permitido. Los orígenes listados se normalizan igual que la URL de destino (minúsculas, sin barra final y sin el puerto por defecto: 'https://cdn.example.com:443/' equivale a 'https://cdn.example.com'); el comodín '*' permite cualquier origen y un array vacío ([]) limita las cargas al mismo origen. Una petición rechazada no se cachea y se trata como un fallo de carga de ese recurso (ver sección 2): un CSS o un HTML rechazado solo genera un aviso, y un JS rechazado hace fallar el componente y activa su contingencia (fallback), si la tiene.

Nota de seguridad: Los atributos de origen (data-e-components-origin, data-e-component-src y sus variantes de contingencia) determinan desde dónde se descarga y ejecuta JavaScript. Si el DOM puede contener HTML proveniente de usuarios (comentarios, perfiles, contenido editable), un atacante podría insertar estos atributos y hacer que la página cargue y ejecute scripts de terceros. En producción se recomienda definir allowedOrigins con los orígenes de confianza (o [] si todos los componentes se sirven desde el mismo origen).

// Solo se permiten el mismo origen y el CDN propio
_components({ allowedOrigins: ['https://cdn.example.com'] });

Inicialización manual con opciones

Las opciones del segundo argumento tienen prioridad sobre los atributos del elemento. Equivalen a los atributos de la sección 2: component, id, origin (carpeta base, como data-e-components-origin), src, componentOrder, required, fallback, fallbackSrc, fallbackOrder, timeout y files; en un coordinador, components y order. A diferencia de _components.scan(), cada llamada crea una instancia nueva aunque el elemento ya tenga una: la anterior sale del registro y la nueva recibe un ID renombrado (ej. saludo_1).

var contenedor = document.querySelector('#ficha_usuario');

// Monta el componente y obtiene su instancia
var componente = _components(contenedor, {
	component: 'perfil-cliente',
	id: 'tarjeta_activa'
}).ref();

2. Atributos en el DOM

Los componentes y sus relaciones se declaran en el HTML con los siguientes atributos.

Atributos de componente (data-e-component-*)

  • data-e-component (String): Nombre del componente, que es también el nombre de su carpeta: los archivos se piden en origen + nombre + '/'. Si no se indica data-e-component-id, también es su ID.
  • data-e-component-id (String): ID de la instancia en el registro. Si el ID ya está registrado, la librería lo renombra secuencialmente (ej. id_1) y emite una advertencia en la consola; esto también ocurre entre hijos de coordinadores distintos. Un coordinador solo reutiliza una instancia existente si pertenece al mismo elemento. Nota: los mensajes enviados al ID original no llegan a las instancias renombradas.
  • data-e-component-src (String): Ruta completa de la carpeta del componente para esta instancia (ej. https://cdn.example.com/ui/boton/). Sustituye a origen + nombre: el nombre del componente no se añade. Si no termina en /, se añade.
  • data-e-component-order (String): Recursos que se cargan y en qué orden (por defecto: "css,html,js"). Admite + para cargas en paralelo (ej. "css+html,js") y alias registrados con _components.order(). Un recurso que no figura no se carga.
  • data-e-component-required (String): IDs de los componentes que deben estar listos ("ready") antes de cargar este, separados por comas o espacios. Las dependencias deben existir cuando este componente empieza a cargarse (por ejemplo, en un paso anterior del orden): si un ID no corresponde a ninguna instancia registrada ni a un nombre del orden del coordinador, el componente falla. Si una de esas dependencias falla, este componente también falla, sin intentar su contingencia. Dentro de un coordinador, un componente con este atributo (con IDs o con "true") es crítico: si falla, el coordinador detiene la orquestación. Con "false" o sin el atributo, su fallo no detiene los pasos siguientes.
  • data-e-component-fallback (String): Nombre del componente de contingencia que se carga, con el mismo ID, si falla la carga principal. Se busca como cualquier otro componente (origen + nombre + '/'), salvo que se indique una ruta de contingencia.
  • data-e-component-fallback-src (String): Ruta completa de la carpeta del componente de contingencia, como data-e-component-src.
  • data-e-component-fallback-order (String): Orden de carga de los recursos del componente de contingencia (por defecto: "css,html,js").
  • data-e-component-timeout (Number): Tiempo máximo de cada petición de esta instancia, en milisegundos.

Si falla la carga del CSS o del HTML, la librería emite un aviso en consola y continúa. Si falla el JS (error de red, tiempo agotado o una excepción al ejecutarlo), el componente falla y se carga su contingencia, si la tiene. El CSS y el JS de cada URL se aplican una sola vez por página (hasta _components.resetCache()): si varias instancias usan el mismo componente, el HTML se inserta en cada una, pero el JS solo se ejecuta con la primera.

Atributos de coordinador (data-e-components-*)

  • data-e-components (String): Marca el nodo como coordinador de los componentes que contiene. Su valor es el ID con el que se registra el coordinador, que se puede usar con _components.get(), en data-e-component-required o en el observador de estado. Un coordinador inicializado con _components(elemento) o _components.scan() necesita un valor no vacío; los coordinadores anidados dentro de un componente cargado pueden omitirlo, y en ese caso no se registran.
  • data-e-components-origin (String): Carpeta base de los componentes: cada uno se pide en origen + nombre + '/'. Se hereda: cada componente usa el data-e-components-origin más cercano (en el propio elemento o en un ascendiente) y, si no hay ninguno, la opción global origin. Para fijar la carpeta exacta de un solo componente, use data-e-component-src.
  • data-e-components-order (String): Orden de carga de los componentes hijos, indicados por su valor de data-e-component (ver sección 3). Admite alias registrados con _components.order(). Solo se cargan los hijos que figuran en él (sin este atributo, ninguno). Cada nombre carga el primer hijo con ese data-e-component: si varios hijos comparten nombre, los demás no se cargan.
  • data-e-components-fallback-origin (String): Ruta de contingencia que heredan los componentes que no declaran data-e-component-fallback-src; se usa la más cercana (en el propio elemento o en un ascendiente). Funciona como data-e-components-origin: es una carpeta base a la que se añade el nombre del componente de contingencia (ej. con ./respaldo/ y data-e-component-fallback="aviso" se carga ./respaldo/aviso/). En cambio, data-e-component-fallback-src es la carpeta completa del componente de contingencia.
  • data-e-components-fallback-order (String): Orden de carga de contingencia que heredan los componentes que no declaran data-e-component-fallback-order; se usa el más cercano (en el propio elemento o en un ascendiente).

Herencia de atributos de contingencia

Si un componente que pasa a su contingencia no declara data-e-component-fallback-src ni data-e-component-fallback-order, la librería busca hacia arriba en el árbol DOM el data-e-components-fallback-origin y el data-e-components-fallback-order más cercanos. La contingencia se intenta una sola vez: si también falla, el componente pasa a "failed".

Componente y coordinador en el mismo nodo

Si un nodo tiene data-e-component y data-e-components, primero se carga el componente y, cuando alcanza el estado "ready", se inicia el coordinador sobre el contenido cargado, también cuando el nodo es hijo de otro coordinador. Las dos instancias conviven: _components.get() encuentra el componente por su ID y el coordinador por el valor de data-e-components.

3. Orquestación

El atributo data-e-components-order de un coordinador define el orden de carga de sus componentes hijos con dos operadores:

  • Coma (,): Pasos sucesivos: un paso empieza cuando todos los componentes del paso anterior han terminado.
  • Suma (+): Componentes del mismo paso, que se cargan en paralelo.

Ejemplo de orquestación

Los nombres del orden corresponden al valor de data-e-component de cada hijo, no a su ID: menu-lateral se encuentra por su nombre aunque su ID sea menu_izq.

<!-- Carga 'estructura-base' y 'menu-lateral' en paralelo. Cuando ambos terminan, carga 'panel-de-control'.
     Se inicia con _components.scan() o con _components(elemento) sobre el div. -->
<div data-e-components="mi_dashboard" data-e-components-order="estructura-base+menu-lateral, panel-de-control">
	<div data-e-component="estructura-base"></div>
	<aside data-e-component="menu-lateral" data-e-component-id="menu_izq"></aside>
	<article data-e-component="panel-de-control" data-e-component-required="menu_izq"></article>
</div>

Alias de orden

_components.order(name, value) registra un orden con un nombre, y _components.order(name) lo devuelve. El alias se usa como valor completo de cualquier atributo de orden (data-e-components-order, data-e-component-order y los de contingencia); no se puede combinar con otros pasos en el mismo valor. Registre los alias antes de iniciar los componentes que los usan:

_components.order('dashboard', 'estructura-base+menu-lateral, panel-de-control');
_components.order('solo-html', 'html');

// <div data-e-components="mi_dashboard" data-e-components-order="dashboard">…</div>
// <div data-e-component="aviso" data-e-component-order="solo-html"></div>

_components.order('dashboard'); // 'estructura-base+menu-lateral, panel-de-control'

4. Ciclo de vida y estados

Las instancias de componente que devuelve .ref() (o _components.get(id)) exponen:

  • id (String): ID final de la instancia en el registro.
  • element (HTMLElement): Elemento del DOM asociado.
  • options (Object): Opciones resueltas de la instancia.
  • on(event, callback), once(event, callback), off(event, callback) y emit(event, data): Suscripción y envío de eventos de la instancia (ver sección 5).
  • status(): Devuelve el estado actual de la instancia:
    • "pending": Registrada y todavía sin iniciar. Es un estado momentáneo, porque la carga empieza al crear la instancia (los hijos de un coordinador se crean cuando llega su paso). También es lo que devuelve status() de una instancia destruida (por ejemplo, porque su elemento salió del DOM).
    • "loading": Esperando a sus componentes requeridos, o descargando y aplicando sus recursos.
    • "loading-fallback": La carga principal ha fallado y empieza la del componente de contingencia. Es un estado momentáneo que se notifica al observador de estado (sección 6): la instancia de contingencia, que usa el mismo ID, pasa enseguida a "loading", y ese es el estado que devuelve status() mientras se carga.
    • "ready": Carga completada y JS ejecutado sin errores (un fallo del CSS o del HTML solo genera un aviso y no lo impide).
    • "failed": Fallo definitivo: falló su JS (y su contingencia, si la tenía) o una de sus dependencias. El elemento recupera sus atributos y contenido originales.

Los coordinadores devuelven un objeto más simple, con id, element y options; su estado se sigue con el observador de estado (sección 6) o declarándolos en data-e-component-required.

API avanzada (interna): _destroy(isReset) desconecta la instancia del observador del DOM, ejecuta sus tareas de limpieza y la elimina del registro. La librería lo llama sola cuando el elemento sale del DOM o con _components.resetCache(); el parámetro isReset evita el aviso que se emite si el elemento sigue conectado. Como indica el prefijo _, no forma parte de la API estable.

5. Eventos de instancia

Cada instancia de componente permite añadir listeners con on(), once() y off():

var inst = _components(document.getElementById('saludo')).ref();

if (inst) {
	// El componente ha terminado de cargarse
	inst.on('ready', function(data) {
		// data es undefined, o { replacedBy: instancia } si se cargó la contingencia
		console.log('Componente insertado en el DOM.');
	});

	// Fallo definitivo: red, tiempo agotado, excepción en su JS o dependencia fallida
	inst.on('error', function(err) {
		console.error('Fallo del componente:', err.message);
	});

	// Evento propio, enviado con _components.emit('saludo', 'refrescar', datos)
	inst.on('refrescar', function(datos) {
		console.log('Datos recibidos:', datos);
	});
}

El evento error recibe siempre un objeto Error; si procede de una excepción del JS del componente, su name es el ID del componente. Si la instancia ya está en "ready" cuando se añade el listener (por ejemplo, porque todos sus recursos estaban en caché), ready no se vuelve a emitir: compruebe antes status(). Los hijos de un coordinador solo existen desde que empieza su paso; antes, _components.get(id) devuelve undefined.

Cola de eventos

Los eventos enviados con _components.emit() a un componente que aún no existe o no está en estado "ready" se guardan en una cola, con un máximo de 50 por ID (los siguientes se descartan con un aviso en consola). Cuando el componente alcanza "ready", la cola se vacía en orden y de forma síncrona, antes de emitir ready; así, el JS del componente puede registrar sus listeners con _components.get(id).on() y recibir los eventos enviados antes. Si el componente pasa a "failed", los eventos en cola se descartan, y los que se envíen después se descartan con un aviso.

6. Métodos globales

La librería expone estas funciones en el objeto _components:

  • _components.get(id): Devuelve la instancia registrada con ese ID, o undefined.
  • _components.emit(targetId, event, data): Envía un evento a una instancia de componente. Si aún no está lista, el evento se guarda en la cola (ver sección 5). Si el ID es de un coordinador, emite un aviso en consola y descarta el evento.
  • _components.order(name, value?): Registra o devuelve un alias de orden de carga (ver sección 3). Volver a registrar un alias sustituye su valor para las cargas siguientes.
  • _components.scan(root?): Inicializa los coordinadores ([data-e-components]) que hay dentro de root, sin incluir el propio root, o dentro de document.body si se omite. Se omiten los elementos que ya tienen una instancia registrada (llamarlo varias veces no los duplica) y los coordinadores que están dentro de un componente, o sobre él, cuando ese componente pertenece a otro coordinador o es él mismo un coordinador: se inician al cargar el componente. Tras iniciarse, cada coordinador inicia también sus subcoordinadores directos que no están dentro de uno de sus componentes. Los componentes que no están dentro de un coordinador se inicializan con _components(elemento).
  • _components.autoScan(): Ejecuta _components.scan() cuando el documento está listo (de inmediato, si ya lo está).
  • _components.resetCache(): Libera memoria. Destruye todas las instancias del registro, retira los observadores, vacía las cachés de recursos (las cargas siguientes vuelven a descargar y aplicar el CSS y el JS) y la cola de eventos, y elimina los observadores de estado registrados. Conserva la configuración global y los alias de orden, y no retira los estilos ya insertados.

Observador de estado (API avanzada)

_components._registerStateObserver(fn) y _components._unregisterStateObserver(fn) permiten recibir todos los cambios de estado de componentes y coordinadores, por ejemplo para telemetría o una barra de carga global. La librería los usa internamente para resolver las dependencias; como indica el prefijo _, no forman parte de la API estable.

function monitorDeEstados(id, nuevoEstado) {
	console.log('[Ciclo de vida] Componente "' + id + '" pasó al estado: ' + nuevoEstado);
}

// Registro
_components._registerStateObserver(monitorDeEstados);

// Baja
// _components._unregisterStateObserver(monitorDeEstados);

7. Características técnicas

Peticiones compartidas y caché: Las peticiones simultáneas del mismo recurso (mismo tipo y URL) comparten una sola descarga. Las respuestas se guardan en una caché en memoria de hasta 100 entradas; al superarse, se elimina la más antigua que no esté en curso (si todas lo están, el límite se supera temporalmente). Un HTML en caché se vuelve a insertar sin nueva petición.

Reintento tras fallo: Cuando la descarga o la aplicación de un recurso falla (error de red, tiempo agotado o excepción al ejecutarlo), el error se notifica a todas las instancias que esperaban ese recurso y la entrada se elimina de la caché. Así, un intento posterior del mismo recurso hace una nueva petición en lugar de reutilizar el error.

Errores en el JS de los componentes: El código JS de cada componente se envuelve en un bloque try/catch antes de ejecutarse; por eso las declaraciones let, const y class de su nivel superior no son globales (var y function sí). Si lanza una excepción, la librería la marca con el ID del componente (en e.name) y la vuelve a lanzar, de modo que aparece en la consola del navegador; un valor que no es un objeto (p. ej. throw 'texto') se convierte antes en un Error con ese mensaje. Un listener global de error reconoce esas excepciones y la carga del componente se considera fallida.

Listener global de errores: El listener de error que la librería registra en window solo reacciona a las excepciones marcadas por la librería e ignora el resto, incluidos los errores sin event.error, como los de scripts de otro origen.

Contingencia y traspaso de eventos: Si falla el JS de un componente que tiene contingencia (fallback), la librería retira del registro la instancia fallida y crea la de contingencia con el mismo ID. Los eventos en cola y los listeners de la instancia original se transfieren a la nueva, salvo los de ready y error: esos se quedan en la original, que los emite al terminar la contingencia (ready recibe { replacedBy: instanciaDeContingencia }). Desde ese momento, _components.get(id) devuelve la nueva instancia, y la referencia anterior ya no admite on(), once(), off() ni emit() (emite un aviso).

Limpieza al salir del DOM: La librería usa un único MutationObserver sobre el body del documento, que comprueba tras cada cambio en el árbol si el elemento de cada instancia sigue en el DOM. Cuando se ha retirado (por ejemplo, al cambiar de vista con un router), se llama a su _destroy(): la instancia sale del registro y se cancelan sus esperas de dependencias.
