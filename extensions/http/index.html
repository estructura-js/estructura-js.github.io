HTTP

Description

Low-level library for asynchronous HTTP requests based on the native XMLHttpRequest object. It lets you control the lifecycle of each request: timeout, custom headers, cross-origin credentials, upload and download progress, and cancellation. It can be used with callbacks or with promises (async/await).

Library: estructura.http.js

Compatibility: ES3/ES5+

Status: RC2

License: AGPL v3

Import:

<script src="https://estructura.okzgn.com/extensions/http/estructura.http.js"></script>

Documentation

Quick start

A GET request that receives the JSON response already parsed; any failure (HTTP, network, timeout, or invalid JSON) reaches onError.

_http({
	url: '/api/users',
	responseType: 'json',
	onSuccess: function(users) {
		console.log('Users:', users);
	},
	onError: function(err) {
		console.error('Failure (' + err.type + '):', err.message);
	}
});

1. Usage and return value

The library exposes a single global function, _http.

_http(options):

Starts a request configured according to the options object.

Syntax:

var req = _http({ url: './config.json' });
// req.abort();
// req.getXHR();
// var res = await req; // inside an async function; or req.then(...), req.catch(...), req.finally(...)

Synchronously returns a control object with the following methods:

  • abort(): Cancels the request in progress and, if defined, invokes onAbort.
  • getXHR(): Returns the underlying XMLHttpRequest object, to inspect or manipulate it at a low level.
  • then(onFulfilled, onRejected), catch(onRejected), and finally(fn): Present only if the environment has Promise. They make the control object a thenable, so it can be used directly with await. They return a native promise, not the control object: keep the latter if you need abort(). The internal promise is created only when one of these methods is invoked (if the request has already finished, it settles immediately with that outcome); that is why, if only callbacks are used, no unhandled rejection warnings occur.

In environments without Promise (ES3/ES5), the control object only has abort() and getXHR(). Callbacks receive the same arguments with or without Promise, and they can be combined with then or await in the same request.

Resolution value: { data, text, status, headers, xhr }.

  • data: The body parsed as JSON if responseType is 'json' or if the response’s Content-Type header is JSON (for example, application/json or application/problem+json); an empty body produces null. In the second case, if parsing fails, it contains the raw text.
  • text: The raw response text (responseText), always untransformed.
  • status: The HTTP status code.
  • headers: An object with the response headers, with lowercase names (repeated values are joined with ", ").
  • xhr: The XMLHttpRequest instance.

Rejection value: An Error instance with the properties type ('http', 'network', 'timeout', 'abort', or 'parse'), status, and xhr. It is the same kind of object that onError receives. With type: 'http', the body of the error response is in error.xhr.responseText.

Note: If the options are not valid (they are not an object, or url is not a non-empty String), the extension throws an exception that the Estructura core catches and shows in the console, with a delay of up to one second; the call still returns an object, but without methods (abort, getXHR, then...). In that case there is no request, no callbacks, and no promise, and an await on that object does not throw: it returns the empty object itself. The same happens if preparing the request fails, for example with an invalid method or a data value with circular references.

2. Options

The options object accepts the following properties:

Syntax:

_http({
	url: 'https://backend.com/api/v1/setData',
	method: 'POST',
	data: { 'a': '1', 'N': '...' }
});
  • url (String): The address of the resource. Required. Note: If it is omitted, is not a String, or is empty, an exception is thrown before the request is opened (see the note on invalid options in section 1).
  • method (String): The HTTP method (e.g., "GET", "POST", "PUT", "DELETE"). Default: "GET".
  • headers (Object): Key-value pairs with the headers that are added to the request through setRequestHeader.
  • data (Any): The request body. If omitted, the request is sent without a body (null). It accepts strings, plain objects and arrays, FormData instances, URLSearchParams, Blob objects, documents, and binary buffers (ArrayBuffer and its views). Note: Except with GET and HEAD (which send no body; this also means the JSON header, which would force a CORS preflight request, is not added), if JSON is available, plain objects and arrays are serialized with JSON.stringify(), and the Content-Type: application/json;charset=UTF-8 header is added, unless headers already defines a Content-Type (the comparison is case-insensitive). All other types, including already serialized strings, are passed untransformed to the native send() method; if you send a JSON string, define the Content-Type in headers yourself. With FormData, it is best not to define Content-Type in headers, so that the browser adds the multipart type with its boundary. data is not added to the URL: with GET or HEAD the browser sends no body, so the parameters must go in url.
  • responseType (String): With the value 'json', the body of a successful response is parsed as JSON before it is delivered: onSuccess receives the parsed value (an empty body produces null) and, if parsing fails, onError is invoked with an error of type 'parse' instead of onSuccess. It does not modify the native xhr.responseType property, so xhr.responseText remains available. If omitted, onSuccess receives the raw text. Any other value is ignored: the response is always read as text, so the library is not suitable for binary downloads.
  • timeout (Number): Time limit in milliseconds. With 0 (the default), there is no limit.
  • withCredentials (Boolean): With true, sends credentials (cookies, authorization headers) in cross-origin requests (CORS).

3. Callbacks

Callbacks are also defined in options and are invoked at different stages of the request:

Status and completion:

  • onSuccess(response, xhr): Invoked when the request finishes with a status code between 200 and 299. It receives as its first argument the response text or, with responseType: 'json', the already parsed value (for example, an object), and as its second argument the XHR instance. Without responseType: 'json', it receives the text even if the response has a JSON Content-Type: automatic parsing based on that header applies only to data in the promise.
  • onError(error, xhr): Invoked on network failures or requests blocked by the browser (CORS, status 0), responses with a status outside the 2xx range (including 3xx responses that the browser has not followed, and 4xx and 5xx responses), parsing failures with responseType: 'json', and timeouts if onTimeout is not defined. It receives as its first argument an Error instance with the properties type ('http', 'network', 'timeout', or 'parse'), status, and xhr, and as its second argument the XHR instance.
  • onHeadersReceived(headersString, xhr): Invoked when the response headers are received (readyState === 2). It receives the raw string returned by getAllResponseHeaders().
  • onReadyStateChange(readyState, status, xhr): A low-level listener invoked on every readyState change after the request is opened: 2, 3 (it can repeat while the response arrives), and 4.

Progress and cancellation:

  • onProgress(loaded, total, percent): Invoked while the response is downloading, when the total size is known (the event’s lengthComputable property). It receives the bytes received, the total bytes, and the percentage. Note: lengthComputable depends on the response including the Content-Length header; without it, the callback is not invoked.
  • onUploadProgress(loaded, total, percent): Same as onProgress, but for uploading the request body. It is registered on xhr.upload if the browser provides it. Note: Registering listeners on xhr.upload forces the browser to send a CORS preflight request for cross-origin requests, so the server must respond to OPTIONS.
  • onTimeout(xhr): Invoked when the timeout limit is exceeded. If omitted, the error is delivered to onError with type: 'timeout'.
  • onAbort(xhr): Invoked when the request is canceled with the control object’s abort() method.

4. Outcome and errors

Warning when combining callbacks:

If onReadyStateChange is defined together with onSuccess, onError, or onHeadersReceived, the library shows a warning in the console. It is informational only: all callbacks are still invoked independently, so it is best not to handle the same states in both.

Single outcome:

Each request has a single outcome: success, error, timeout, or cancellation. The first one to occur is recorded, and later native events are ignored. Therefore, only one of onSuccess, onError, onTimeout, and onAbort is invoked, and only once; the promise resolves or rejects with that same outcome. onReadyStateChange, onHeadersReceived, and the progress callbacks are not part of the outcome and are still invoked normally.

  • Status 200–299: onSuccess; the promise resolves.
  • Status other than 2xx and greater than 0: onError; rejection with type: 'http'.
  • Network failure, CORS, or blocked request (status 0): onError; rejection with type: 'network'.
  • Timeout: onTimeout (or onError if it is not defined); rejection with type: 'timeout'.
  • Cancellation with abort(): onAbort; rejection with type: 'abort'.
  • Invalid JSON with responseType: 'json': onError; rejection with type: 'parse'.

Status 0:

Requests that do not complete their communication with the server (DNS failure, lost connection, CORS block, or other browser restrictions) end with status equal to 0. According to the XMLHttpRequest specification, the native error, timeout, and abort events fire after the change to readyState === 4. That is why, when the library detects that state with code 0, it defers the decision with setTimeout(0): if one of those events has already determined the request’s outcome in that interval, that outcome is respected (network failure, timeout, or cancellation); if not, onError is invoked with the error 'Request failed with status 0 (network/CORS/blocked): ' + url. This way, every failure with status 0 is reported exactly once. Note: Some browsers return status 0 for successful requests to file:// URLs; the library still treats them as a network error.

Cancellation:

The abort() method stops the request in progress. Although cancellation leaves the native status at 0, the abort event is recorded before the deferred status-0 check runs; if the browser does not dispatch that event synchronously, the abort() method itself records the cancellation. In both cases only onAbort is invoked, never onError. Calling abort() on a request that has already finished does not change its outcome, although the browser resets the XHR object (status becomes 0 and responseText is emptied). The promise’s resolution value is not affected: the text, the status, and the headers are saved at the moment of success.

5. Examples

GET request with a JSON response

With responseType: 'json', onSuccess receives the parsed value, and invalid JSON reaches onError as type: 'parse'. Without responseType, onSuccess receives the raw text: this is the right choice for responses that are not JSON, or when you want to parse it yourself and handle invalid JSON without going through onError.

_http({
	url: 'https://api.example.com/v1/users',
	method: 'GET',
	responseType: 'json',
	onSuccess: function(users, xhr) {
		console.log('Processed user list:', users);
	},
	onError: function(err, xhr) {
		// err.type: 'http' | 'network' | 'timeout' | 'parse'
		console.error('Failure (' + err.type + '):', err.message);
	}
});

POST upload with progress and timeout

var uploadControl = _http({
	url: 'https://api.example.com/v1/files',
	method: 'POST',
	headers: {
		'X-Client-Identifier': 'Estructura-App'
	},
	// Serialized as JSON, and Content-Type: application/json;charset=UTF-8 is added
	data: { fileId: 'doc_09182' },
	timeout: 10000,
	onUploadProgress: function(loaded, total, percent) {
		console.log('Data upload progress: ' + percent.toFixed(2) + '%');
	},
	onSuccess: function(response, xhr) {
		console.log('Processing completed successfully:', response);
	},
	onTimeout: function(xhr) {
		console.error('The server exceeded the 10-second response limit.');
	},
	onError: function(err, xhr) {
		console.error('The upload could not be completed:', err.message);
	}
});

Canceling a request

var request = _http({
	url: 'https://api.example.com/v1/data-stream',
	onSuccess: function(response, xhr) {
		console.log('Data received:', response);
	},
	onAbort: function(xhr) {
		console.log('The request was canceled before it finished.');
	}
});

// Cancel the request when the user clicks a button
document.querySelector('#cancel-action').addEventListener('click', function() {
	request.abort();
});

Usage with promises and async/await (ES6+)

In environments with Promise, the control object returned by _http() can be awaited directly. Callbacks remain optional and compatible with this usage:

async function getUserData() {
	try {
		var response = await _http({
			url: 'https://api.example.com/v1/profile',
			timeout: 5000
		});
		// data is parsed if the server responds with a JSON Content-Type
		console.log('Data obtained:', response.data, response.status, response.headers['content-type']);
	}
	catch (error) {
		// error.type: 'http' | 'network' | 'timeout' | 'abort' | 'parse'
		console.error('Error caught with async/await (' + error.type + ', ' + error.status + '):', error.message);
	}
}

// Also with then/catch/finally, keeping the ability to cancel
var request = _http({ url: '/api/status' });
request
	.then(function(response) { console.log(response.text); })
	.catch(function(error) { console.error(error.type); })
	.finally(function() { console.log('Done'); });
// request.abort();

6. Technical details

Own properties only: Only the own properties of the headers object are sent; properties inherited from the prototype are ignored.

Untransformed body: Except for plain objects and arrays, which are serialized as JSON, data is passed as is to send(), so the browser determines the associated headers (for example, the multipart/form-data boundary with FormData).
