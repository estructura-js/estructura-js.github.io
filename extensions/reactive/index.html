Reactive

Descripción

Proporciona enlace de datos bidireccional entre un objeto de estado y el DOM. Sincroniza el estado del script con la interfaz de usuario mediante plantillas con delimitadores configurables (por defecto, {{ variable }}). Las actualizaciones del DOM se agrupan y se aplican de forma asíncrona, en una microtarea.

Librería: estructura.reactive.js

Compatibilidad: ES6+

Estado: RC2

Licencia: AGPL v3

Importación:
<!-- EXTENSIÓN: Estructura / Reactive -->
<script src="https://estructura.okzgn.com/extensions/reactive/estructura.reactive.js"></script>

Documentación

1. Inicialización y estado

Inicialice la reactividad pasando como raíz cualquier elemento del DOM (por lo general, el contenedor de la vista) o document, en cuyo caso se usa document.documentElement. Las plantillas se compilan y se renderizan por primera vez de forma síncrona al crear la instancia. Acceda al estado reactivo mediante el objeto Proxy devuelto por el método .state().

// Inicializar reactividad sobre el documento
var miReactivo = _reactive(document.documentElement);

// Obtener el objeto de estado
var state = miReactivo.state();

// Escribir propiedades en el estado
state.miVariable = 'Hola Mundo';
// El DOM se actualiza en la siguiente microtarea, no en esta línea

Nombres reservados: on, off, stop y event son métodos del estado y no pueden usarse como variables: asignarlos lanza un error. Tampoco se admiten claves Symbol.

Fallos de inicialización: si la raíz no es un nodo válido, la configuración no es un objeto o una plantilla es incorrecta (por ejemplo, un enlace bidireccional con dos variables), _reactive() no lanza el error: lo muestra en la consola con hasta un segundo de retraso y devuelve un objeto sin el método state().

Raíces anidadas: evite crear una instancia dentro de la raíz de otra. La primera que compila una plantilla la sustituye por su valor, y la otra ya no la encuentra.

2. Configuración avanzada

El constructor acepta un segundo argumento opcional (Object) para configurar delimitadores personalizados de plantillas y procesadores de nombres y expresiones.

Opciones de configuración:

  • variables_prefix (String): delimitador de apertura de la plantilla (por defecto, "{{").
  • variables_postfix (String): delimitador de cierre de la plantilla (por defecto, "}}").
  • variables_preprocessor (Function): callback que se ejecuta al extraer cada plantilla. Recibe el texto entre delimitadores (sin los espacios de los extremos) y un objeto de metadatos ({ expr, start, end }). Lo que retorne se usa como nombre de la variable (o como texto de la expresión); si retorna un valor falso, la plantilla se ignora y queda como texto literal.
  • variables_processor (Function): callback que calcula el valor inicial de una expresión. Se ejecuta una sola vez, al registrarse la expresión. Recibe la clave virtual (String), el texto de la expresión (String) y el estado (Object), y lo que retorne se guarda en el estado.
  • sanitizer (Function | false): sanitizador propio de la instancia para los valores interpolados en atributos, en lugar de _reactive.sanitize. Con false se desactiva la sanitización en esta instancia (ver Sanitización).

Ejemplo de configuración:

var miReactivo = _reactive(document.documentElement, {
	variables_prefix: '[[',
	variables_postfix: ']]',
	variables_preprocessor: function(name, meta){
		// Ignorar variables específicas retornando un valor falso
		if(name === 'ignore_me') return null;
		return meta.expr ? name : name.toLowerCase();
	},
	variables_processor: function(key, expr, state){
		try {
			var keys = Object.keys(state);
			var vals = keys.map(function(k){ return state[k]; });
			return new Function(keys, 'return (' + expr + ')').apply(null, vals);
		} catch(e){ return ''; }
	}
});

Advertencia: evaluar expresiones con new Function equivale a usar eval. Requiere que la política CSP permita 'unsafe-eval' y nunca debe usarse con plantillas que puedan contener contenido de usuarios.

3. Plantillas y expresiones

La librería clasifica automáticamente el texto entre delimitadores en dos categorías:

  • Identificadores simples: si el texto (sin los espacios de los extremos) solo contiene letras ASCII, dígitos, _ o $ y no empieza por un dígito (ej. nombre, mi_variable), se registra directamente como variable del estado y se actualiza cada vez que esta cambia. Un nombre con tildes o eñes (año) se trata como expresión.
  • Expresiones: si el texto contiene operadores, espacios internos o rutas de objeto (ej. user.name o a + b), se trata como expresión y se le asigna una clave virtual basada en su posición dentro del texto (ej. _e_7_18). La misma expresión usa siempre la misma clave, también en nodos distintos; si dos expresiones distintas ocupan la misma posición, la segunda recibe un sufijo (ej. _e_7_18_2). El preprocesador también recibe las expresiones, con meta.expr en true.

Importante: el valor de una expresión se calcula una sola vez, al registrarse, mediante variables_processor (sin procesador, queda vacío). No se recalcula cuando cambian las variables que usa: en {{a + b}} o {{user.name}}, modificar state.a o state.user no actualiza el texto renderizado. Además, el procesador solo ve los valores que el estado tenga en ese momento. Para cambiar lo que muestra una expresión, asigne el nuevo valor a su clave virtual (la reciben variables_processor y el evento createdVariable) o, mejor, calcule el valor en JavaScript y use una variable simple.

Enlace unidireccional

Se aplica en nodos de texto y en atributos comunes (como class, src, id, etc.). Admite varias variables o expresiones en un mismo texto. En los atributos booleanos disabled, checked, readonly, required y selected, un valor falso (o el texto 'false') quita el atributo y cualquier otro lo añade. Los demás atributos booleanos (como hidden u open) se tratan como atributos comunes: siguen presentes aunque el valor sea vacío.

<!-- Nodos de texto con identificadores y expresiones -->
<h1>Bienvenido, {{nombre}} {{apellido}}</h1>
<p>Operación: {{1 * 2}}</p>
<p>Ruta anidada: {{user.name}}</p>

<!-- Atributos -->
<div class="alerta {{tipo_alerta}}" id="{{id_registro}}"></div>
<button disabled="{{bloqueado}}">Enviar</button>

Enlace bidireccional

Lleva al estado los cambios que el usuario hace en la interfaz, mediante los eventos input y change del nodo raíz. Se aplica al atributo value (o checked en casillas y botones de opción) y al texto de los elementos <textarea>. En sentido contrario, cada cambio del estado se refleja en el control, también en un <textarea> que el usuario ya haya editado. Estos enlaces solo admiten una variable: con más de una, la inicialización falla (ver Fallos de inicialización).

<!-- Input de texto -->
<input type="text" value="{{miVariable}}">

<!-- Control booleano -->
<input type="checkbox" checked="{{activo}}">

<!-- Textarea -->
<textarea>{{miVariable}}</textarea>

4. Ciclo de vida

El estado expone métodos para activar, pausar o apagar la instancia.

  • state.on(): compila las plantillas del nodo raíz, renderiza todas las variables y activa los listeners input/change y el MutationObserver. Se ejecuta automáticamente al crear la instancia; puede llamarse de nuevo después de stop() para reanudar.
  • state.stop(): retira los listeners input/change, desconecta el MutationObserver y descarta las actualizaciones pendientes, sin perder los registros ni los datos del estado. Las asignaciones posteriores al estado siguen actualizando los nodos ya registrados.
  • state.off(): llama a stop() y después elimina los registros de nodos y variables. Los valores del estado se conservan. Como las plantillas ya renderizadas no conservan sus delimitadores, state.on() no recupera esos enlaces.

5. Eventos del ciclo de vida

Permite suscribir callbacks a eventos del ciclo de vida de las variables y de la instancia mediante state.event(). Cada evento admite un único callback: registrar otro reemplaza el anterior. Si un callback lanza un error, se relanza con el nombre del evento en el mensaje.

Sintaxis:

state.event('createdVariable', function(name){
	console.log('Variable registrada:', name);
});

Eventos soportados:

  • createdVariable: se dispara cuando aparece en el DOM una variable que aún no existe en el estado. Recibe el nombre de la variable (String; en las expresiones, su clave virtual).
  • deletedVariable: se dispara cuando una variable pierde todas sus vinculaciones con nodos del DOM. Recibe el nombre de la variable (String); su valor se conserva en el estado.
  • beforeMutateVariable: se dispara antes de actualizar un nodo del DOM. Recibe la variable (String), el valor que se va a escribir (el texto completo resultante del nodo o atributo; en los atributos booleanos, true o false), el elemento contenedor (Element), el nodo que cambia (texto o atributo) y el nombre del atributo ('textContent' en los nodos de texto).
  • afterMutateVariable: se dispara tras actualizar el nodo. Recibe los mismos argumentos que beforeMutateVariable.
  • reactiveOn: se dispara al llamar a state.on(). No se dispara en el arranque inicial, porque en ese momento aún no hay callbacks registrados.
  • reactiveStop: se dispara al llamar a state.stop(), y también a state.off().
  • reactiveOff: se dispara al llamar a state.off(), después de reactiveStop.

6. Sanitización

Cada vez que se renderiza un atributo interpolado (excepto los booleanos), el texto resultante pasa por _reactive.sanitize(value, ctx) antes de escribirse, donde ctx es { type: 'attribute', name, element, variable }. La función retorna el valor que finalmente se escribe (también el que reciben los eventos beforeMutateVariable/afterMutateVariable). Los nodos de texto no pasan por ella.

Qué se filtra por defecto:

  • En atributos de URL (href, src, action, formaction, xlink:href, poster, cite, background), los esquemas javascript: y vbscript: se neutralizan: se escribe '' y se emite un console.warn.
  • data: solo se permite en src y poster, y únicamente para data:image/, data:video/ o data:audio/.
  • Antes de comparar el esquema se eliminan espacios y caracteres de control y se pasa a minúsculas, ya que los navegadores aceptan variantes como java\tscript:.
  • Se bloquea cualquier atributo interpolado cuyo nombre empiece por on (sin distinguir mayúsculas), sea o no un manejador de eventos, como onclick="{{accion}}": se escribe '' y se emite un console.warn. Solo se exceptúan los atributos que coinciden con una propiedad booleana del elemento (los elementos nativos no tienen ninguna que empiece por on; puede darse en elementos personalizados).

Qué no se filtra, y por qué: el texto (textContent, ya es seguro), value y checked (enlace bidireccional: alterarlos desincronizaría el estado), los atributos booleanos, class, id, style, data-* y aria-*, porque no ejecutan código. Los sinks HTML (srcdoc) pasan sin cambios: filtrar HTML de forma fiable requiere un parser completo, por lo que se delega en una librería especializada.

Reemplazar o extender: asigne su propia función a _reactive.sanitize (afecta a todas las instancias que no definan sanitizer), o use la opción sanitizer por instancia. Para conservar las reglas por defecto, guarde la original y llámela desde la nueva.

HTML:

<div id="app">
	<a href="{{enlace}}">Enlace</a>
	<iframe srcdoc="{{contenido}}"></iframe>
</div>
<div id="panel"><a href="{{destino}}">Contenido de confianza</a></div>

JavaScript:

// Conectar DOMPurify para los sinks HTML, manteniendo las reglas por defecto
var sanitizeDefault = _reactive.sanitize;

_reactive.sanitize = function(value, ctx){
	if(ctx.name === 'srcdoc'){ return DOMPurify.sanitize(String(value)); }
	return sanitizeDefault(value, ctx);
};

var state = _reactive(document.getElementById('app')).state();
state.enlace = 'java\tscript:alert(1)'; // Escribe '' y avisa en consola

// Desactivar la sanitización en una instancia concreta (#panel está fuera de #app)
var confiable = _reactive(document.getElementById('panel'), { sanitizer: false });

7. Características técnicas

Actualización asíncrona por microtareas: las asignaciones al estado no actualizan el DOM de inmediato. Se agrupan y se aplican juntas en una microtarea (Promise.resolve().then), así que tras state.x = 1 el DOM todavía no ha cambiado. Para leer el DOM actualizado, espere una microtarea (por ejemplo, await Promise.resolve() dentro de una función async). Asignar el mismo valor que ya tenía no genera actualización.

Compilación inicial síncrona: al crear la instancia (o al llamar a state.on()), las plantillas se compilan y se renderizan en el mismo paso.

MutationObserver: detecta nodos y atributos añadidos, eliminados o modificados dentro del nodo raíz, registra las plantillas nuevas y retira del registro los nodos eliminados. Los nodos añadidos después del arranque se registran, pero no se renderizan hasta el siguiente cambio de alguna de sus variables. Antes de actualizar un nodo se comprueba si sigue conectado (.isConnected); los nodos desconectados se retiran del registro en lugar de actualizarse.

Memoria: usa WeakMap para asociar plantillas y registros a los nodos, de modo que los nodos retirados del registro pueden liberarse.
