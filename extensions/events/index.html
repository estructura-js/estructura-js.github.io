Events

Descripción

Gestiona eventos del DOM. Con namespaces, registro por modos (once, capture, passive, signal) y opciones para pausar, reanudar, disparar manualmente o eliminar eventos.

Librería: estructura.events.js

Compatibilidad: ES5/ES6+

Estado: RC2

Licencia: AGPL v3

Importación:
<!-- EXTENSIÓN: Estructura / Events -->
<script src="https://estructura.okzgn.com/extensions/events/estructura.events.js"></script>

Demo en vivo

Haga clic en cualquier parte de la página. Un listener registrado con _events(document.body).on('click', fn, { capture: true }) muestra la etiqueta del elemento pulsado.

Elemento pulsado: ninguno

Documentación

1. Inicialización y control global

  • _events: función global de la librería.
  • _events.pause(): detiene globalmente, en todos los objetivos, la ejecución de los eventos registrados. Mientras está en pausa, tampoco tienen efecto .off() ni los disparos manuales (incluida la reactivación con resume); los nuevos registros con .on(event, fn) sí se guardan.
  • _events.resume(): reactiva globalmente la ejecución de todos los eventos registrados.
  • _events(target): selecciona el objetivo sobre el que se aplican los métodos. Puede ser un nodo del DOM (Node), una lista de nodos (NodeList o HTMLCollection; cada método se aplica a cada nodo de la lista), document, window o cualquier Object con las funciones addEventListener y removeEventListener. Si el objetivo no es válido (por ejemplo, null porque querySelector no encontró nada), el resultado no tiene .on() ni .off() y la llamada lanza un TypeError.
  • .on(), .off(), .load() y .ready() retornan el mismo objeto, por lo que se pueden encadenar: _events(boton).on('click', fn).on('keyup', fn2).

2. Registro de eventos

.on(event?, fn?, config?): vincula callbacks a eventos del objetivo. El nombre del evento va siempre primero: .on(fn) sin evento se ignora con un aviso en la consola.

Sintaxis:

_events(document.querySelector('body')).on('event.namespace', function(){}, {})

Argumentos:

event (String):

Nombre del evento. Opcionalmente puede incluir un namespace tras un punto para identificar el registro (ver Namespaces). Se pueden indicar varios eventos en la misma cadena, separados por comas o espacios: 'click, keyup.ns'.

  • Los nombres de evento se pasan a minúsculas (salvo DOMContentLoaded). Por eso un evento propio con mayúsculas que se despache con dispatchEvent (por ejemplo, 'miEvento') no llega a los callbacks: use nombres en minúsculas.
  • El prefijo on se elimina ('onclick' equivale a 'click' y 'onfocusin' a 'focusin'), salvo en eventos cuyo nombre real empieza por «on»: 'online', o cualquier nombre cuyo manejador 'on' + nombre exista en el objetivo.
  • Si la cadena, quitando los separadores del inicio y del final, tiene menos de 2 caracteres (por ejemplo, 'x'), la llamada se ignora. Una cadena vacía (''), en cambio, equivale a no indicar event.

fn (Function):

Callback vinculado al evento; recibe como primer argumento el objeto Event, y this es el objetivo. Si se omite, .on() dispara manualmente los callbacks registrados (ver Ejecución manual).

config (Object):

Configuración general:

  • overwrite: si es true, reemplaza los callbacks previos de ese mismo evento, namespace y modo por el nuevo.
  • resume: si es true (en un disparo manual, sin fn), reactiva los eventos pausados que coincidan, sin ejecutarlos.
  • execute: si es true junto con resume, además ejecuta en ese momento todos los callbacks que coincidan, estuvieran pausados o no. Como resume y execute no son opciones de modo, actúan en todos los modos del evento, salvo que config incluya también once, capture, passive o signal.

Configuración específica (modo):

  • once: si es true, el callback se ejecuta la primera vez que ocurre el evento y después se elimina (los disparos manuales no cuentan; ver Ejecución manual).
  • capture: si es true, se usa la fase de captura del DOM.
  • passive: si es true, el listener es pasivo: preventDefault() no tiene efecto (útil en scroll/touch).
  • signal: un AbortSignal. Cada señal distinta forma su propio modo, con su propio listener nativo. Al abortarse, el navegador retira ese listener y la librería elimina su registro, de modo que el evento se puede volver a registrar. Con una señal ya abortada, el registro se ignora.

Cada combinación de once, capture, passive y signal es un modo distinto con su propio listener nativo.

Ejemplos:

Registrar un evento con namespace:

var target = document.querySelector('a');

_events(target).on('click.miMenu', function(e){
	console.log('Clic detectado');
});

Registrar en varios eventos a la vez; con once, cada uno se ejecuta una sola vez:

_events(target).on('click.aviso, keyup.aviso', function(e){
	console.log('Primera vez:', e.type);
}, { once: true });

Registrar con un AbortSignal:

var controller = new AbortController();

_events(window).on('resize.temporal', function(){
	console.log('Redimensionado');
}, { signal: controller.signal });

controller.abort(); // Retira el listener y su registro

3. Eliminación de eventos

.off(event?, config?): elimina registros de eventos, de forma selectiva mediante nombre y namespace, o todos a la vez.

Argumentos:

event (String): nombre del evento que se desvinculará. Opcionalmente puede incluir un namespace para identificar el registro, o ser solo el namespace ('.miMenu'), y admite varios eventos separados por comas o espacios. Sigue las mismas reglas que en .on(): con menos de 2 caracteres la llamada se ignora, y una cadena vacía equivale a .off(), que lo elimina todo.

config (Object):

Configuración general:

  • pause: si es true, pausa los eventos que coincidan sin eliminarlos. Se reactivan con .on(event, { resume: true }).

Configuración específica (modo):

Sin opciones de modo, .off() actúa sobre el evento en todos sus modos. Si config incluye alguna (capture, once, passive o signal, aunque valga false), solo actúa sobre el modo que resulta de esa combinación exacta: { capture: true } no afecta a un registro hecho con { capture: true, once: true }. Para signal hay que pasar el mismo objeto AbortSignal usado al registrar ({ signal: miSignal }); signal: true no coincide con ningún registro.

Sin nombre de evento: config se pasa como primer argumento, y entonces las opciones de modo no filtran. .off({ pause: true }) pausa todos los eventos del objetivo, pero .off({ capture: true }) los elimina todos. No pase undefined ni null como primer argumento con config en el segundo: la configuración se ignora y .off() lo elimina todo.

Ejemplos:

  • Elimina solo el evento del namespace indicado: 
    _events(target).off('click.miMenu')
  • Elimina solo los registros de click hechos con capture: true (y sin otras opciones de modo): 
    _events(target).off('click', { capture: true })
  • Elimina solo los registros de resize hechos con una señal concreta (se pasa el mismo objeto AbortSignal): 
    _events(window).off('resize', { signal: controller.signal })
  • Pausa la ejecución de todos los eventos del tipo sin desvincularlos del DOM: 
    _events(target).off('click', { pause: true })
  • Reactiva los eventos pausados sin ejecutarlos: 
    _events(target).on('click', { resume: true })
  • Reactiva los eventos pausados y ejecuta en ese momento todos los callbacks de click: 
    _events(target).on('click', { resume: true, execute: true })
  • Pausa y reactiva todos los eventos del objetivo: 
    _events(target).off({ pause: true });
_events(target).on({ resume: true });
  • Elimina todos los eventos vinculados al objetivo: 
    _events(target).off()

4. Namespaces

La librería permite identificar registros con un namespace tras un punto (.). Así se pueden tener varios callbacks para el mismo evento en el mismo elemento y eliminarlos o dispararlos por separado.

_events(window).on('resize.layout', fn1);
_events(window).on('resize.analytics', fn2);

// Eliminar solo analytics sin tocar layout:
_events(window).off('resize.analytics');

Todo lo que sigue al primer punto forma un único identificador: en 'click.a.b' el namespace es a.b, no dos namespaces. Por eso .off('.a') no elimina ese registro; hay que usar .off('.a.b').

A diferencia del nombre del evento, el namespace distingue mayúsculas y minúsculas: .off('.mimenu') no elimina 'click.miMenu'. Un namespace sin nombre de evento sirve para eliminar o disparar, pero no para registrar: .on('.miMenu', fn) se ignora.

5. Ejecución manual

Es posible ejecutar los callbacks registrados sin que ocurra el evento nativo del DOM. Al utilizar .on() sin fn, el primer argumento (event) acepta el nombre del evento, solo el namespace (comenzando con punto) o ambos. En un disparo manual los callbacks reciben un objeto vacío ({}) en lugar del objeto Event.

  • El segundo argumento es config: además de resume y execute, admite opciones de modo para ejecutar solo los registros de ese modo (por ejemplo, .on('click', { capture: true })). Sin nombre de evento, config va en el primer argumento (.on({ resume: true })).
  • Los callbacks pausados no se ejecutan (salvo con resume y execute).
  • Un disparo manual no consume los registros once: el callback se ejecuta y sigue registrado hasta que ocurre el evento nativo. Para ejecutarlo y eliminarlo, use .on('click', { once: true }).
  • Si un callback lanza un error, el error no llega a quien llama: el núcleo de Estructura lo captura y lo muestra en la consola con hasta un segundo de retraso.

Ejemplos:

Ejecuta solo los eventos del namespace registrado:

_events(target).on('.miEvento');

Ejecuta todos los eventos registrados de ese tipo:

_events(target).on('click');

Ejecuta todos los eventos registrados:

_events(target).on();

6. Eventos especiales

Atajos para eventos de ciclo de vida. Registran un listener normal, así que si el evento ya ocurrió el callback no se ejecuta. Admiten config como segundo argumento y, sin fn, disparan manualmente los callbacks registrados para ese evento:

  • Al terminar de cargar toda la página (load): 
    _events(window).load(fn)
  • Al terminar de cargar el DOM de la página (DOMContentLoaded): 
    _events(document).ready(fn)

7. Consideraciones técnicas

  • Memoria: la librería usa WeakMap cuando está disponible. En navegadores sin WeakMap, use .off() antes de retirar nodos del DOM para evitar fugas de memoria.
  • Configuración: el listener nativo de cada modo se crea con la configuración del primer registro de ese modo y la sigue leyendo en cada evento. No modifique el objeto config después de registrarlo: si cambia una opción de modo, los callbacks de ese modo dejan de ejecutarse.
  • Sobrescritura: overwrite: true reemplaza los callbacks dentro del mismo evento, namespace y modo. No cambia el modo de un registro existente: registrar con otras opciones (por ejemplo, passive: false en lugar de true) crea un listener distinto; para cambiarlo, elimine antes el anterior con .off().
  • Duplicados: a diferencia de addEventListener, registrar dos veces la misma función hace que se ejecute dos veces.
  • once y pausa: la librería retira un registro once después de ejecutarlo. Si el evento ocurre mientras está pausado, no se ejecuta ni se retira: se ejecutará una vez tras reactivarlo.
  • Errores: si un callback lanza un error, el resto se ejecuta igualmente y al final se lanza un único error con todos los mensajes. En un evento nativo aparece en la consola como error no capturado; en un disparo manual lo captura el núcleo (ver Ejecución manual).
