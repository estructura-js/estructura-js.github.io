Events

Description

Manages DOM events, with namespaces, registration by mode (once, capture, passive, signal), and options to pause, resume, manually trigger, or remove events.

Library: estructura.events.js

Compatibility: ES5/ES6+

Status: RC2

License: AGPL v3

Import:
<!-- EXTENSION: Estructura / Events -->
<script src="https://estructura.okzgn.com/extensions/events/estructura.events.js"></script>

Live demo

Click anywhere on the page. A listener registered with _events(document.body).on('click', fn, { capture: true }) shows the tag name of the clicked element.

Clicked element: none

Documentation

1. Initialization and global control

  • _events: the library’s global function.
  • _events.pause(): globally stops registered events from running, on all targets. While paused, .off() and manual triggers (including resuming with resume) have no effect either; new registrations with .on(event, fn) are still stored.
  • _events.resume(): globally resumes the execution of all registered events.
  • _events(target): selects the target the methods apply to. It can be a DOM node (Node), a list of nodes (NodeList or HTMLCollection; each method is applied to every node in the list), document, window, or any Object with the addEventListener and removeEventListener functions. If the target is not valid (for example, null because querySelector found nothing), the result has no .on() or .off(), so calling them throws a TypeError.
  • .on(), .off(), .load(), and .ready() return the same object, so they can be chained: _events(button).on('click', fn).on('keyup', fn2).

2. Registering events

.on(event?, fn?, config?): binds callbacks to the target’s events. The event name always comes first: .on(fn) without an event is ignored, and a warning is logged to the console.

Syntax:

_events(document.querySelector('body')).on('event.namespace', function(){}, {})

Arguments:

event (String):

The event name. It can optionally include a namespace after a dot to identify the registration (see Namespaces). Several events can be given in the same string, separated by commas or spaces: 'click, keyup.ns'.

  • Event names are lowercased (except DOMContentLoaded). That is why a custom event with uppercase letters that is dispatched with dispatchEvent (for example, 'myEvent') does not reach the callbacks: use lowercase names.
  • The on prefix is removed ('onclick' is equivalent to 'click', and 'onfocusin' to 'focusin'), except for events whose actual name starts with “on”: 'online', or any name whose 'on' + name handler exists on the target.
  • If the string, after removing leading and trailing separators, has fewer than 2 characters (for example, 'x'), the call is ignored. An empty string (''), on the other hand, is equivalent to not passing event (except when registering: .on('', fn) is ignored without a warning in the console).

fn (Function):

Callback bound to the event; it receives the Event object as its first argument, and this is the target. If omitted, .on() manually triggers the registered callbacks (see Manual execution).

config (Object):

General configuration:

  • overwrite: if true, replaces the previous callbacks for that same event, namespace, and mode with the new one.
  • resume: if true (in a manual trigger, without fn), resumes the matching paused events without running them.
  • execute: if true together with resume, also runs all matching callbacks at that moment, whether or not they were paused. Since resume and execute are not mode options, they act on all of the event’s modes, unless config also includes once, capture, passive, or signal.

Mode-specific configuration:

  • once: if true, the callback runs the first time the event occurs and is then removed (manual triggers do not count; see Manual execution).
  • capture: if true, the DOM capture phase is used.
  • passive: if true, the listener is passive: preventDefault() has no effect (useful for scroll/touch).
  • signal: an AbortSignal. Each different signal forms its own mode, with its own native listener. When the signal is aborted, the browser removes that listener and the library deletes its registration, so the event can be registered again. If the signal is already aborted, the registration is ignored.

Each combination of once, capture, passive, and signal is a different mode with its own native listener.

Examples:

Register an event with a namespace:

var target = document.querySelector('a');

_events(target).on('click.myMenu', function(e){
	console.log('Click detected');
});

Register for several events at once; with once, each one runs only once:

_events(target).on('click.notice, keyup.notice', function(e){
	console.log('First time:', e.type);
}, { once: true });

Register with an AbortSignal:

var controller = new AbortController();

_events(window).on('resize.temporary', function(){
	console.log('Resized');
}, { signal: controller.signal });

controller.abort(); // Removes the listener and its registration

3. Removing events

.off(event?, config?): removes event registrations, selectively by name and namespace, or all at once.

Arguments:

event (String): the name of the event to unbind. It can optionally include a namespace to identify the registration, or be only the namespace ('.myMenu'), and it accepts several events separated by commas or spaces. It follows the same rules as in .on(): with fewer than 2 characters the call is ignored, and an empty string is equivalent to .off(), which removes everything.

config (Object):

General configuration:

  • pause: if true, pauses the matching events without removing them. They are resumed with .on(event, { resume: true }).

Mode-specific configuration:

Without mode options, .off() acts on the event in all its modes. If config includes any of them (capture, once, passive, or signal, even if set to false), it acts only on the mode that results from that exact combination: { capture: true } does not affect a registration made with { capture: true, once: true }. For signal, you must pass the same AbortSignal object used when registering ({ signal: mySignal }); signal: true does not match any registration.

Without an event name: config is passed as the first argument, and mode options then do not act as filters. .off({ pause: true }) pauses all the target’s events, but .off({ capture: true }) removes all of them. Do not pass undefined or null as the first argument with config as the second: the configuration is ignored and .off() removes everything.

Examples:

  • Removes only the event with the given namespace: 
    _events(target).off('click.myMenu')
  • Removes only the click registrations made with capture: true (and no other mode options): 
    _events(target).off('click', { capture: true })
  • Removes only the resize registrations made with a specific signal (the same AbortSignal object is passed): 
    _events(window).off('resize', { signal: controller.signal })
  • Pauses the execution of all events of that type without unbinding them from the DOM: 
    _events(target).off('click', { pause: true })
  • Resumes the paused events without running them: 
    _events(target).on('click', { resume: true })
  • Resumes the paused events and runs all the click callbacks at that moment: 
    _events(target).on('click', { resume: true, execute: true })
  • Pauses and resumes all the target’s events: 
    _events(target).off({ pause: true });
_events(target).on({ resume: true });
  • Removes all the events bound to the target: 
    _events(target).off()

4. Namespaces

The library lets you identify registrations with a namespace after a dot (.). This way you can have several callbacks for the same event on the same element and remove or trigger them separately.

_events(window).on('resize.layout', fn1);
_events(window).on('resize.analytics', fn2);

// Remove only analytics without touching layout:
_events(window).off('resize.analytics');

Everything after the first dot forms a single identifier: in 'click.a.b' the namespace is a.b, not two namespaces. That is why .off('.a') does not remove that registration; you have to use .off('.a.b').

Unlike the event name, the namespace is case-sensitive: .off('.mymenu') does not remove 'click.myMenu'. A namespace without an event name can be used to remove or trigger, but not to register: .on('.myMenu', fn) is ignored.

5. Manual execution

You can run the registered callbacks without the native DOM event occurring. When .on() is used without fn, the first argument (event) accepts the event name, only the namespace (starting with a dot), or both. In a manual trigger, the callbacks receive an empty object ({}) instead of the Event object.

  • The second argument is config: in addition to resume and execute, it accepts mode options to run only the registrations of that mode (for example, .on('click', { capture: true })). Without an event name, config goes in the first argument (.on({ resume: true })).
  • Paused callbacks do not run (except with resume and execute).
  • A manual trigger does not consume once registrations: the callback runs and stays registered until the native event occurs. To run it and remove it, use .on('click', { once: true }).
  • If a callback throws an error, the error does not reach the caller: the Estructura core catches it and shows it in the console with a delay of up to one second.

Examples:

Runs only the callbacks registered with that namespace:

_events(target).on('.myEvent');

Runs all the registered events of that type:

_events(target).on('click');

Runs all the registered events:

_events(target).on();

6. Special events

Shortcuts for lifecycle events. They register a normal listener, so if the event has already occurred, the callback does not run. They accept config as the second argument and, without fn, manually trigger the callbacks registered for that event:

  • When the whole page has finished loading (load): 
    _events(window).load(fn)
  • When the page’s DOM has finished loading (DOMContentLoaded): 
    _events(document).ready(fn)

7. Technical considerations

  • Memory: the library uses WeakMap when it is available. In browsers without WeakMap, use .off() before removing nodes from the DOM to avoid memory leaks.
  • Configuration: the native listener of each mode is created with the configuration of that mode’s first registration and keeps reading it on every event. Do not modify the config object after registering it: if a mode option changes, the callbacks of that mode stop running.
  • Overwriting: overwrite: true replaces the callbacks within the same event, namespace, and mode. It does not change the mode of an existing registration: registering with other options (for example, passive: false instead of true) creates a different listener; to change it, first remove the previous one with .off().
  • Duplicates: unlike addEventListener, registering the same function twice makes it run twice.
  • once and pausing: the library removes a once registration after running it. If the event occurs while it is paused, it neither runs nor is removed: it will run (and be removed) the next time the event occurs after it is resumed.
  • Errors: if a callback throws an error, the rest still run, and at the end a single error with all the messages is thrown. In a native event, it appears in the console as an uncaught error; in a manual trigger, the core catches it (see Manual execution).
